# catalog/semantic-search Specification

## Purpose
Эмбеддинги вакансий и резюме: фоновая индексация, похожие вакансии, смысловой поиск в
фильтрах каталога и подбор вакансий под резюме.

## Requirements

### Requirement: Индексация вакансий
Лидер API MUST раз в `ai.embeddings.sweep_interval_seconds` считать эмбеддинги уникальных вакансий без вектора, с вектором другой модели или изменённых после него — не больше `max_per_sweep` за проход, активные и свежие первыми, по `batch_size` текстов в запросе. Вакансия, у которой изменился только `updated_at`, а текст и модель те же, SHALL обновлять отметку без запроса к провайдеру. Ошибка провайдера MUST останавливать проход до следующего интервала. `enabled: false` — индексации нет.

#### Scenario: Повторный проход без изменений
- **WHEN** все вакансии проиндексированы и не менялись
- **THEN** следующий проход не обращается к провайдеру

#### Scenario: Сменили модель
- **WHEN** вектор вакансии посчитан моделью A, а настроена B
- **THEN** проход пересчитывает его моделью B

### Requirement: Похожие вакансии
`GET /vacancies/{id}/similar` MUST отдавать ближайшие по косинусу активные уникальные вакансии с `similarity` = 1 − расстояние, без самой вакансии и без вакансий ближе `ai.embeddings.near_duplicate_distance` (тот же текст с правками), не больше двух от одной компании (`company_key`). Вакансия без вектора текущей модели — пустой список с `pending: true`; несуществующая — 404.

#### Scenario: Поток однотипных постов компании
- **WHEN** у компании пять очень похожих вакансий, у другой компании — одна
- **THEN** в ответе две вакансии первой компании и вакансия второй

#### Scenario: Вектор прежней модели
- **WHEN** у вакансии вектор модели, отличной от настроенной
- **THEN** ответ — пустой список с `pending: true`

### Requirement: Смысловой поиск
С `q` и `search_mode=semantic` фильтр каталога MUST оставлять до 300 ближайших к вектору запроса вакансий под остальными фильтрами — одинаково для списка, метрик, аналитики и экспорта. При сортировке по умолчанию (`post_date` без второй ступени) список SHALL идти по близости. Вектор запроса недоступен (эмбеддинги выключены, нет ключа, ошибка провайдера) — 503 `UPSTREAM_UNAVAILABLE`.

#### Scenario: Фильтр внутри окна
- **WHEN** смысловой запрос «python» с фильтром грейда `senior`
- **THEN** в ответе только вакансии грейда `senior`

#### Scenario: Эмбеддинги выключены
- **WHEN** `ai.embeddings.enabled: false`, запрос с `search_mode=semantic`
- **THEN** ответ 503 `UPSTREAM_UNAVAILABLE`

### Requirement: Подбор под резюме
`sort_by=resume_fit` MUST требовать `resume_id` своего резюме (без него — 422) и упорядочивать вакансии по близости к эмбеддингу резюме; вакансии без вектора — в конце, свежие первыми. Эмбеддинг резюме SHALL храниться и пересчитываться только при смене текста или модели.

#### Scenario: Повторный запрос
- **WHEN** список с `resume_fit` запрошен дважды без правки резюме
- **THEN** вектор резюме посчитан один раз

#### Scenario: Вакансия без вектора
- **WHEN** часть вакансий ещё не проиндексирована
- **THEN** они идут после проиндексированных

### Requirement: Инструкция для запроса и резюме
Текст смыслового запроса MUST отправляться провайдеру как `Instruct: {ai.embeddings.query_instruction}\nQuery:{текст}`, текст резюме — так же с `resume_instruction`; пустая инструкция — текст как есть. Тексты вакансий SHALL отправляться без инструкции. Смена инструкции резюме MUST пересчитывать его сохранённый вектор.

#### Scenario: Запрос с инструкцией
- **WHEN** `query_instruction` задана, запрос «Python FastAPI»
- **THEN** провайдер получает `Instruct: <инструкция>\nQuery:python fastapi`

#### Scenario: Сменили инструкцию резюме
- **WHEN** вектор резюме посчитан с одной инструкцией, а настроена другая
- **THEN** следующий подбор пересчитывает вектор резюме

### Requirement: Только векторы текущей модели
Смысловой поиск, подбор под резюме, «Похожие» и резюме на карте MUST сравнивать вектор только с векторами вакансий той же модели, что настроена в `ai.embeddings.model`; вакансия с вектором другой модели SHALL считаться вакансией без вектора.

#### Scenario: Каталог переиндексируется
- **WHEN** часть вакансий ещё с вектором прежней модели
- **THEN** смысловой поиск их не находит, а подбор под резюме ставит их в конец
