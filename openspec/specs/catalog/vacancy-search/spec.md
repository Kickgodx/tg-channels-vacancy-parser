# catalog/vacancy-search Specification

## Purpose
Список и карточка вакансий общего каталога: фильтры, полнотекстовый поиск,
сортировка, пагинация и проверка параметров. Фильтры списка — общие для метрик,
аналитики и экспорта.

## Requirements

### Requirement: Список сужается фильтрами каталога
Список вакансий MUST содержать только уникальные вакансии (без дублей дедупа), по умолчанию без архивных (см. `catalog/vacancy-retention`). Фильтры SHALL сочетаться через «и»: канал (`source_channel`, ведущий `@` отбрасывается), грейд, формат работы, любая из выбранных специализаций, любая из технологий, дата поста от и до включительно по UTC, `has_salary`: `true` — только с рублёвой суммой, `false` — только без неё. Те же фильтры MUST действовать в метриках, аналитике и экспорте.

#### Scenario: Несколько специализаций
- **WHEN** выбраны специализации `Backend` и `QA`
- **THEN** в списке вакансии, у которых есть хотя бы одна из них

#### Scenario: Специализация и технология
- **WHEN** выбраны специализация `Automation QA` и технология `Python`
- **THEN** в списке только вакансии `Automation QA`, у которых среди технологий есть `Python`

#### Scenario: Канал с `@`
- **WHEN** фильтр — `source_channel=@jobs`
- **THEN** список тот же, что при `source_channel=jobs`

#### Scenario: Граница периода
- **WHEN** `date_to=2026-09-30`, а пост опубликован 30 сентября в 23:59 UTC
- **THEN** вакансия входит в список

#### Scenario: Зарплата есть только в исходной валюте
- **WHEN** у вакансии A рублёвая сумма 150 000, у B зарплата 1 000 в валюте без курса, у C зарплаты нет
- **THEN** с `has_salary=true` в списке только A, с `has_salary=false` — B и C
- **AND** метрики с `has_salary=true` считают одну вакансию с зарплатой

### Requirement: Полнотекстовый поиск по тексту вакансии
Параметр `q` (до 500 символов) MUST искать по очищенному тексту вакансии полнотекстовым поиском русской конфигурации: слова сравниваются по основе, поддерживается синтаксис веб-поиска (фразы в кавычках, исключение через `-`). Первые 1000 совпадений в выбранной сортировке SHALL идти по релевантности, остальные — за ними в выбранной сортировке; `total` считает все. Так же — в экспорте.

#### Scenario: Другая форма слова
- **WHEN** пользователь ищет «разработчик», а в тексте вакансии «разработчиков»
- **THEN** вакансия найдена, вакансии без этого слова — нет

#### Scenario: Релевантность внутри окна
- **WHEN** совпадений меньше 1000, и у более старой вакансии слово встречается чаще, чем у новой
- **THEN** более старая вакансия идёт в выдаче раньше

#### Scenario: Совпадение за пределами окна
- **WHEN** совпадений 1001, и самое старое из них по сортировке `post_date desc` релевантнее всех остальных
- **THEN** оно идёт в выдаче последним, `total` — 1001

### Requirement: Сортировка списка
`sort_by` MUST принимать `post_date` (по умолчанию), `detected_salary_avg`, `detected_salary_avg_rub`, `work_format`, `detected_grade`, `salary_currency`, `vacancy_score` и `match_score` (см. `career/resume-matching`); другое значение — 422. `match_score` без `resume_id` (в том числе в экспорте и списке вакансий прогона) SHALL давать 422 `VALIDATION`. `sort_order` — `asc` или `desc` (по умолчанию). Пустые значения идут в конце при любом направлении. Равные по полю (кроме `post_date` и `match_score`) SHALL идти от новых постов к старым, затем по `id`; при сортировке по `post_date` и `match_score` равные — по `id`.

Вторая ступень `then_by` (с `then_order`, по умолчанию `desc`) MUST быть доступна в списке, экспорте и пресетах только для пары `post_date` ↔ `detected_salary_avg_rub`; другое сочетание (в том числе поле с самим собой) — 422 `VALIDATION`. `sort_by=post_date` с `then_by=detected_salary_avg_rub` SHALL сортировать по дню поста по UTC, внутри дня — по рублёвой зарплате (пустая — в конце), затем по времени поста в направлении дня. `sort_by=detected_salary_avg_rub` с `then_by=post_date` — при равной зарплате по дате в направлении `then_order`.

#### Scenario: Зарплата в рублях по убыванию
- **WHEN** у трёх вакансий рублёвая зарплата 300 000, пусто и 150 000, сортировка — `detected_salary_avg_rub`
- **THEN** порядок: 300 000, 150 000, без зарплаты

#### Scenario: Равная зарплата
- **WHEN** у двух вакансий рублёвая зарплата 150 000, одна опубликована 10 октября, другая — 12-го, сортировка — `detected_salary_avg_rub`
- **THEN** вакансия от 12 октября идёт раньше
- **AND** с `then_by=post_date&then_order=asc` — позже

#### Scenario: Внутри дня — по зарплате
- **WHEN** 20 октября (UTC) опубликованы A в 10:00 с зарплатой 100 000, B в 08:00 с 300 000 и C в 12:00 без зарплаты, 19 октября в 23:30 UTC — E с 500 000; запрос `sort_by=post_date&then_by=detected_salary_avg_rub`
- **THEN** порядок: B, A, C, E

#### Scenario: Вторая ступень вне пары
- **WHEN** `sort_by=work_format&then_by=detected_salary_avg_rub`
- **THEN** ответ 422 `VALIDATION`

#### Scenario: Недопустимое поле
- **WHEN** `sort_by=raw_text`
- **THEN** ответ 422 `VALIDATION`

#### Scenario: Сортировка по оценке без резюме
- **WHEN** список запрошен с `sort_by=match_score` без `resume_id`
- **THEN** ответ 422 `VALIDATION`, сообщение говорит, что нужен `resume_id`

### Requirement: Список листается до 10 000 позиций
`page` MUST быть от 1, `page_size` — от 1 до 500 (по умолчанию 50). Страница дальше 10 000 позиций (`page × page_size`) SHALL давать 422 `VALIDATION` с советом уточнить фильтры. Ответ содержит `total` — число вакансий под фильтрами; страница за последней — пустая, с тем же `total`.

#### Scenario: Последняя доступная страница
- **WHEN** `page_size=50` и `page=200`, затем `page=201`
- **THEN** первый ответ 200, второй — 422 `VALIDATION`

#### Scenario: Страница за концом списка
- **WHEN** под фильтрами 5 вакансий, запрошена `page=10` при `page_size=2`
- **THEN** `items` пуст, `total` равен 5

### Requirement: Параметры каталога проверяются
Неверный тип или значение вне границ у фильтров, пагинации и `limit` списка, метрик, аналитики и экспорта MUST давать 422 `VALIDATION` с описанием поля, а не ошибку сервера. Пустой параметр (`date_from=`) SHALL считаться незаданным.

#### Scenario: Неверная дата
- **WHEN** запрошены метрики с `date_from=yesterday`
- **THEN** ответ 422 `VALIDATION`

#### Scenario: Пустой параметр
- **WHEN** список запрошен с `date_from=&date_to=`
- **THEN** ответ 200, фильтр по датам не применяется

### Requirement: Список отдаёт превью, карточка — полный текст
Элемент списка MUST содержать `preview` — начало очищенного текста до 120 символов, с «…» при обрезке — и не содержать `raw_text` и `cleaned_text`. `GET /vacancies/{id}` SHALL отдавать вакансию целиком, с обоими текстами; несуществующий id — 404.

#### Scenario: Длинная вакансия в списке
- **WHEN** очищенный текст вакансии длиннее 120 символов
- **THEN** в списке `preview` из 120 символов и «…», полных текстов нет; в карточке оба текста целиком

#### Scenario: Несуществующая вакансия
- **WHEN** запрошена карточка по неизвестному id
- **THEN** ответ 404

### Requirement: Технология в фильтре специализаций — фильтр по технологии
Фильтр `technology` MUST сравнивать технологии без учёта регистра и алиасов (`golang` — `Go`). Технология, переданная в `specialization` (старые ссылки и пресеты), SHALL считаться фильтром по технологии.

#### Scenario: Язык в старой ссылке
- **WHEN** список запрошен с `specialization=Python`
- **THEN** список тот же, что при `technology=Python`

### Requirement: Варианты фильтра технологий
`GET /vacancies/technologies` MUST отдавать технологии с числом вакансий под фильтрами каталога, кроме собственного выбора технологий, — до `limit` (200, не больше 500), по убыванию числа, при равенстве — по названию.

#### Scenario: Выбранная технология не сужает варианты
- **WHEN** запрос с `technology=Go`, у вакансий технологии `Python` (2) и `Go` (1)
- **THEN** в ответе `Python` 2 и `Go` 1
