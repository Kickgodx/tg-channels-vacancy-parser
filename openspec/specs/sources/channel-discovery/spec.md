# sources/channel-discovery Specification

## Purpose
Кандидаты в источники: каналы, из которых пересылают посты в читаемые каналы, с числом
пересланных вакансий — без лишних запросов к Telegram.

## Requirements

### Requirement: Источник пересылки
Пост MUST получать источник пересылки, только если он переслан из канала (`fwd_from.from_id` — канал): id канала, username (основной или первый активный из списка, в нижнем регистре), название и id поста в источнике. Сведения SHALL браться из сущностей ответа истории, без отдельных запросов к Telegram; нет сущности — только id. Пересылки от пользователей и со скрытым отправителем источника не имеют.

#### Scenario: Пересылка от пользователя
- **WHEN** пост переслан от пользователя
- **THEN** источника пересылки нет

### Requirement: Пересылки прогона
Прогон MUST собирать разобранные посты с источником пересылки: наш канал, id поста, дату, источник и признак, прошёл ли пост как кандидат в вакансии. Пересылка из того же канала SHALL не учитываться. Воркер MUST записывать пересылки после завершения разбора; ошибка записи SHALL логироваться и не менять статус прогона.

#### Scenario: Вакансия и не вакансия
- **WHEN** из канала hub переслали пост-вакансию и пост без вакансии
- **THEN** обе пересылки записаны, у первой `is_vacancy` — `true`, у второй — `false`

### Requirement: Учёт без удвоения
Пересылка MUST храниться по ключу (наш канал, id поста): повторное чтение того же окна SHALL NOT увеличивать счётчики, а пост, хоть раз прошедший как вакансия, остаётся вакансией. Username и название канала MUST обновляться последними увиденными, пустые значения не затирают известные.

#### Scenario: Перечитали окно
- **WHEN** пост, записанный как не вакансия, при перечитывании прошёл как вакансия и пришёл без названия канала
- **THEN** пересылок столько же, пост учтён как вакансия, название канала прежнее

### Requirement: Список кандидатов
`GET /channels/candidates` (только админ, иначе 403) MUST отдавать до 100 каналов с публичным username, которых нет в `sources.channels` и среди каналов с чекпоинтами (без учёта регистра): число пересылок, число пересланных вакансий, наши каналы, куда пересылают, даты первой и последней пересылки и ссылку на пост в источнике. Порядок SHALL быть по числу пересланных вакансий, затем по числу пересылок. Скрытые (`ignored`) отдаются только с `include_ignored=true`.

#### Scenario: Уже читаемый канал
- **WHEN** из канала test_channel, который есть в `config.yaml`, пересылали посты
- **THEN** его нет в списке кандидатов

### Requirement: Скрыть кандидата
`PATCH /channels/candidates/{channel_id}` (только админ) MUST ставить статус `ignored` или `new`; неизвестный канал — 404, иной статус — 422.

#### Scenario: Скрыли и вернули
- **WHEN** админ скрыл кандидата
- **THEN** его нет в списке без `include_ignored`, а с `include_ignored=true` он есть со статусом `ignored`
