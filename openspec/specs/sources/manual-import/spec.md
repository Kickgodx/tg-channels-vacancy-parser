# sources/manual-import Specification

## Purpose

Ручной импорт вакансий из вставленного текста в общую базу: разбор правилами
и LLM, дедупликация по тексту, итог по каждому тексту.

## Requirements

### Requirement: Импорт-задача без запущенного LLM завершается ошибкой
Если импорт ушёл в фоновую LLM-задачу (AI включён, есть новые тексты), а LLM не удалось запустить, задача MUST завершиться статусом `error` в любом `ai.mode`. Необработанные тексты SHALL NOT сохраняться разбором правилами.

#### Scenario: LLM не запускается
- **WHEN** администратор импортирует новый текст при `ai.enabled: true`, а LLM в воркере не запускается
- **THEN** задача получает статус `error`, текст не сохранён в `vacancies`
- **AND** `error_message` задачи называет причину сбоя запуска LLM
- **AND** суточная квота LLM пользователя не списана

#### Scenario: Ретрай после падения воркера
- **WHEN** задача уже записала итог по части текстов, воркер упал, а при повторной попытке LLM не запускается
- **THEN** задача получает статус `error`
- **AND** итог по уже обработанным текстам остаётся в результате задачи

#### Scenario: Исчерпана суточная квота пользователя
- **WHEN** у пользователя кончилась суточная квота LLM посреди импорта
- **THEN** оставшиеся тексты разбираются правилами и сохраняются, задача завершается `done` с предупреждением

### Requirement: Текст, не разобранный из-за потолка вызовов, получает понятный итог
В `ai.mode: primary` текст, оставленный без разбора из-за `ai.max_posts_per_run`, MUST получить в итоге импорта статус `error` с сообщением о лимите вызовов LLM. Текст SHALL NOT сохраняться разбором правилами.

#### Scenario: Потолок в импорте
- **WHEN** в `primary` с `ai.max_posts_per_run: 1` импортируются два новых текста, и ответов в кэше нет
- **THEN** первый текст разобран LLM и сохранён
- **AND** второй получает статус `error` с сообщением, что достигнут лимит `ai.max_posts_per_run`, и не сохранён

### Requirement: Импорт-задачу можно отменить
Владелец импорт-задачи MUST иметь возможность запросить её отмену в статусе `queued` или `running`. Запрос SHALL быть идемпотентным и возвращать текущее состояние задачи с признаком `cancel_requested`. Задача в очереди SHALL сразу получать статус `cancelled`, не обработав ни одного текста.

#### Scenario: Отмена импорта в очереди
- **WHEN** владелец отменяет импорт-задачу в статусе `queued`
- **THEN** задача получает статус `cancelled`, ни один текст не разобран и не сохранён

#### Scenario: Чужая задача
- **WHEN** пользователь запрашивает отмену импорт-задачи другого пользователя
- **THEN** ответ 404, задача продолжается

### Requirement: Отменённый импорт останавливается между текстами
Выполняемая импорт-задача с запрошенной отменой MUST остановиться перед следующим текстом и получить статус `cancelled`. Текст, разбор которого уже идёт, SHALL быть доведён до конца и записан в итог. Уже сохранённые вакансии SHALL NOT удаляться; итог задачи MUST содержать результаты по обработанным текстам.

#### Scenario: Отмена посреди импорта
- **WHEN** из пяти текстов разобраны два, и владелец запрашивает отмену
- **THEN** задача получает статус `cancelled`, оставшиеся тексты не разбираются и не тратят квоту LLM
- **AND** итог задачи содержит результаты по уже обработанным текстам, их вакансии остаются в базе

#### Scenario: Воркер пропал после запроса отмены
- **WHEN** для выполняемого импорта запрошена отмена, а воркер перестал отвечать
- **THEN** после истечения lease задача получает статус `cancelled` и не ставится на повтор

### Requirement: Страница импорта позволяет отменить идущий импорт
Пока страница импорта ждёт фоновую задачу, она MUST показывать кнопку отмены. После отмены страница SHALL показать итог по уже обработанным текстам и сообщение, что импорт отменён.

#### Scenario: Отмена из UI
- **WHEN** администратор нажимает «Отменить» во время импорта
- **THEN** импорт останавливается, на странице видны результаты по обработанным текстам и пометка об отмене

### Requirement: Запрос импорта ограничен
Запрос импорта MUST содержать от 1 до 50 текстов, каждый не длиннее 30 000 символов, и необязательный `source_url` до 2048 символов; иначе — 422. Если все тексты пустые или из одних пробелов, ответ SHALL быть 400 `VALIDATION`, ничего не сохраняется.

#### Scenario: Слишком длинный текст
- **WHEN** администратор импортирует текст длиннее 30 000 символов
- **THEN** ответ 422

#### Scenario: Только пустые тексты
- **WHEN** импортируются тексты `""` и `"   "`
- **THEN** ответ 400 `VALIDATION`

### Requirement: Импорт без LLM выполняется сразу
Если AI выключен или все непустые тексты уже есть в базе, импорт MUST выполняться в запросе: ответ 200 с итогом. Иначе SHALL ставиться задача `kind=import` (см. `platform/durable-jobs`) с ответом 202 `{job_id}`; итог по уже обработанным текстам растёт в `import_result` задачи и приходит в её потоке событий.

#### Scenario: AI включён, тексты новые
- **WHEN** при `ai.enabled: true` импортируются два новых текста
- **THEN** ответ 202, задача `import` завершается `done`, в её итоге два текста

#### Scenario: AI включён, тексты уже в базе
- **WHEN** при `ai.enabled: true` импортируются только тексты, уже сохранённые раньше
- **THEN** ответ 200, задача не создаётся, LLM не вызывается

### Requirement: Итог импорта по каждому тексту
Итог MUST содержать по каждому тексту его индекс и статус: `created` — сохранён, `exists` — такой текст уже в базе (по id вакансии, см. `ingestion/deduplication`), `not_vacancy` — не вакансия, `error` — пустой текст или ошибка разбора, с пояснением. Итог SHALL содержать `created`, `existing`, `rejected` (`not_vacancy` и `error`), `total`, `ai_enabled` и `warning`.

#### Scenario: Пачка с пустым текстом
- **WHEN** импортируются вакансия, пустой текст и ещё одна вакансия при выключенном AI
- **THEN** статусы `created`, `error`, `created`

#### Scenario: Повторный импорт
- **WHEN** текст импортируется второй раз
- **THEN** его статус `exists`, новой вакансии нет

#### Scenario: Один текст дважды в запросе
- **WHEN** в одном запросе два одинаковых новых текста
- **THEN** первый `created`, второй `exists`

### Requirement: Импортированная вакансия — из канала `manual`
Вакансия из импорта MUST сохраняться с каналом `manual`, ссылкой `source_url` в `post_url` и датой поста — моментом импорта. Импорт SHALL NOT привязывать вакансию к прогону и записывать появления.

#### Scenario: Импорт со ссылкой
- **WHEN** импортируется текст с `source_url` `https://hh.ru/vacancy/123`
- **THEN** вакансия видна в списке с `source_channel=manual` и `post_url` `https://hh.ru/vacancy/123`

### Requirement: Импорт не применяет фильтры прогона
Импорт MUST NOT применять пост-фильтры прогона (исключающие слова, формат, локация) и порог оценки (см. `ingestion/rule-extraction`). Без AI SHALL сохраняться любой непустой текст. С AI решение «вакансия или нет» принимает LLM, а `ai.skip_if_vacancy_score_below` не действует: каждый новый текст уходит в модель.

#### Scenario: Не вакансия без AI
- **WHEN** при выключенном AI импортируется текст про пикник
- **THEN** статус `created`, текст сохранён

#### Scenario: Не вакансия с AI
- **WHEN** при включённом AI импортируются вакансия и текст про пикник, LLM признаёт второй не вакансией
- **THEN** статусы `created` и `not_vacancy`, в модель ушли оба текста

### Requirement: Сбой LLM на тексте отражается в итоге текста
Если LLM не разобрал новый текст, итог MUST зависеть от режима (см. `ingestion/ai-extraction`): в `primary` текст получает `error` и не сохраняется; в `assist` SHALL сохраняться разбор правилами с пометкой об ошибке LLM в пояснении текста.

#### Scenario: Отказ модели в primary
- **WHEN** в `ai.mode: primary` модель вернула ошибку на новом тексте
- **THEN** статус `error`, вакансия не сохранена

### Requirement: Квота импорта списывается по текстам
Импорт MUST списывать один вызов суточной квоты пользователя (см. `platform/llm-governance`) на каждый новый текст перед обращением к модели. Пустой текст и текст, уже имеющийся в базе, SHALL NOT тратить квоту.

#### Scenario: Квота на два текста
- **WHEN** импортируются один новый и один уже сохранённый текст
- **THEN** списан один вызов квоты

### Requirement: Повтор импорта продолжает с необработанного текста
После падения воркера задача импорта MUST продолжаться с первого текста без итога: уже обработанные тексты SHALL NOT разбираться и тратить LLM повторно. Вакансия и итог по тексту записываются вместе и только владельцем lease. Таймаут задачи в очереди `rq` растёт с числом текстов.

#### Scenario: Ретрай после сбоя
- **WHEN** у задачи из двух текстов уже записан итог первого, и задача выполняется заново
- **THEN** в модель уходит только второй текст, итог содержит оба

#### Scenario: Lease потерян
- **WHEN** воркер разбирает текст, а lease задачи принадлежит другому воркеру
- **THEN** ни вакансия, ни итог текста не записываются
