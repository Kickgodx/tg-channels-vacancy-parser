# identity/access-control Specification

## Purpose
Кто к каким данным и операциям имеет доступ: аноним, пользователь, администратор;
общие данные (корпус вакансий и всё, что из него строится) и личные данные
пользователя.

## Requirements

### Requirement: Анониму доступны только здоровье и вход
Без access-токена MUST быть доступны только `GET /health`, регистрация и вход (`/auth/register`, `/auth/login`, `/auth/token`) и операции по refresh-cookie (`/auth/refresh`, `/auth/logout`). Любой другой эндпоинт без действующего токена SHALL отвечать 401 `NOT_AUTHENTICATED`.

#### Scenario: Чтение вакансий без токена
- **WHEN** анонимный клиент запрашивает список вакансий, аналитику, курсы, конфигурацию или прогоны
- **THEN** ответ 401 с кодом `NOT_AUTHENTICATED`

#### Scenario: Проверка здоровья
- **WHEN** анонимный клиент запрашивает `GET /health`
- **THEN** ответ 200 со статусом и состоянием БД

### Requirement: Общие данные читает любой вошедший пользователь
Вошедший пользователь MUST иметь чтение общих данных: список, карточку, метрики и экспорт вакансий, аналитику, курсы валют, статистику AI-кэша, конфигурацию по умолчанию и каталог LLM-моделей. Изменение общих данных SHALL быть доступно только администратору.

#### Scenario: Пользователь читает каталог
- **WHEN** пользователь без прав администратора запрашивает список вакансий, статистику AI-кэша и конфигурацию по умолчанию
- **THEN** ответы 200

### Requirement: Прогоны, импорт и HH доступны только администратору
Прогоны парсинга (запуск, отмена, список, карточка, вакансии, экспорт и поток событий), ручной импорт вакансий, все операции HH (статус, sync, история, отмена, поток событий), обновление курсов и пересчёт зарплат в рубли и очистка AI-кэша MUST быть доступны только администратору. Пользователь без прав SHALL получать 403 `FORBIDDEN` до поиска запрошенного объекта, и действие не выполняется.

#### Scenario: Пользователь запускает прогон
- **WHEN** пользователь без прав администратора запускает прогон, импорт, обновление курсов или очистку AI-кэша
- **THEN** ответ 403 `FORBIDDEN`, прогон не создан, данные не изменены

#### Scenario: Пользователь читает прогон
- **WHEN** пользователь без прав администратора запрашивает список, карточку, вакансии, экспорт или поток событий прогона — даже несуществующего
- **THEN** ответ 403 `FORBIDDEN`

#### Scenario: Пользователь открывает HH
- **WHEN** пользователь без прав администратора запрашивает историю HH sync, sync или поток событий sync
- **THEN** ответ 403

### Requirement: Личные данные видит только владелец
Резюме, пресеты фильтров, оценки соответствия, сопроводительные письма и LLM-задачи MUST принадлежать пользователю. Чужой объект SHALL быть для пользователя неотличим от несуществующего: 404, а не 403. Список личных объектов MUST содержать только свои. Администратор не получает доступ к чужим личным данным.

#### Scenario: Чужое резюме
- **WHEN** пользователь запрашивает, оценивает по или удаляет резюме другого пользователя
- **THEN** ответ 404, резюме не изменено

#### Scenario: Список пресетов
- **WHEN** два пользователя сохранили пресеты фильтров
- **THEN** каждый видит в списке только свои

#### Scenario: Чужая LLM-задача
- **WHEN** пользователь запрашивает или отменяет LLM-задачу другого пользователя
- **THEN** ответ 404

#### Scenario: Оценка в списке вакансий по чужому резюме
- **WHEN** пользователь запрашивает список вакансий с `resume_id` чужого резюме
- **THEN** ответ 404

### Requirement: Общий API-ключ дополняет вход
При заданном `API_KEY` каждый запрос, требующий JWT, MUST нести заголовок `X-API-Key` с этим значением, иначе — 401 `NOT_AUTHENTICATED`, и действие не выполняется. Исключения: `/health` и `/auth/*`, кроме выдачи SSE-тикета; поток событий по одноразовому тикету ключа не требует, по `Authorization: Bearer` — требует. Ключ SHALL приниматься только из заголовка. Без `API_KEY` заголовок не нужен.

#### Scenario: Резюме без ключа
- **WHEN** задан `API_KEY`, и пользователь с действующим JWT без `X-API-Key` создаёт резюме
- **THEN** ответ 401 `NOT_AUTHENTICATED`, резюме не создано

#### Scenario: Пресеты и LLM-задачи без ключа
- **WHEN** задан `API_KEY`, и пользователь с JWT без `X-API-Key` запрашивает свои пресеты или свою LLM-задачу
- **THEN** ответ 401 `NOT_AUTHENTICATED`

#### Scenario: С ключом
- **WHEN** задан `API_KEY`, и пользователь с JWT и верным `X-API-Key` запрашивает резюме, пресеты и LLM-задачу
- **THEN** ответы как без `API_KEY`

#### Scenario: Поток событий по тикету
- **WHEN** задан `API_KEY`, пользователь получил SSE-тикет с ключом и открывает поток событий своей LLM-задачи по тикету без `X-API-Key`
- **THEN** поток открывается

#### Scenario: Ключ не задан
- **WHEN** `API_KEY` не задан
- **THEN** запросы с JWT без `X-API-Key` проходят
