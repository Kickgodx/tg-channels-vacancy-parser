# ingestion/ai-extraction Specification

## Purpose

LLM-разбор постов и текстов вакансий: режимы `assist` и `primary`, слияние с
полями правил, кэш ответов и поведение при недоступности LLM.

## Requirements

### Requirement: В primary пост без ответа LLM не сохраняется с полями правил
В `ai.mode: primary` пост, для которого не получен ответ LLM (ни вызовом, ни из кэша) из-за исчерпания `ai.max_posts_per_run`, MUST NOT сохраняться как вакансия с полями правил. Такой пост SHALL учитываться как неразобранный и SHALL NOT кэшироваться.

#### Scenario: Пост сверх потолка в primary
- **WHEN** в `primary` достигнут `ai.max_posts_per_run`, и следующему посту нужен вызов LLM
- **THEN** LLM не вызывается, пост не сохраняется в `vacancies`
- **AND** пост учтён как пропущенный из-за потолка, в кэш LLM ничего не пишется

#### Scenario: Пост сверх потолка в assist
- **WHEN** в `assist` достигнут `ai.max_posts_per_run`, и следующему посту нужен вызов LLM
- **THEN** LLM не вызывается, пост сохраняется с полями правил (`extraction_source = rules`)

### Requirement: Потолок вызовов LLM ограничивает только вызовы, а не ответы из кэша
`ai.max_posts_per_run` MUST ограничивать только число вызовов LLM. Пост, ответ LLM для которого есть в кэше, SHALL разбираться по этому ответу и после достижения потолка — в обоих режимах.

#### Scenario: Ответ из кэша после потолка в primary
- **WHEN** в `primary` достигнут `ai.max_posts_per_run`, а ответ LLM для следующего поста есть в кэше
- **THEN** пост разбирается по ответу из кэша и сохраняется как обычно

#### Scenario: Ответ из кэша после потолка в assist
- **WHEN** в `assist` достигнут `ai.max_posts_per_run`, а ответ LLM для следующего поста есть в кэше
- **THEN** пост разбирается по ответу из кэша (`extraction_source = hybrid`), а не одними правилами
