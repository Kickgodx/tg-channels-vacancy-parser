# Proposal

## Why

Сквозные правила платформы — формат ошибок API, сквозной id запроса, журнал без
секретов, устройство конфигурации и режимы `dev`/`prod`, миграции, плановая
очистка и перенос данных — в `openspec/specs/` не описаны: на них ссылаются
другие спецификации, но самих требований нет. Этап 5 завершает baseline.

## What Changes

- Фиксируется уже реализованное поведение, без изменений кода:
  - соглашения API: единый формат ошибок и код по статусу, ошибка валидации,
    непредвиденная ошибка, `X-Request-ID`, HTTP-журнал и маскирование секретов,
    CORS;
  - конфигурация: `config.yaml` и переменные окружения, подхват правок без
    рестарта, ошибки конфигурации, режимы `APP_ENV`, запрет `dev` на внешнем
    адресе, только Postgres, ошибки настроек без значений, конфигурация для UI,
    проверка здоровья;
  - обслуживание данных: миграции при старте, очистка по срокам хранения,
    удаление ненужных служебных записей, хранение курсов, очистка пачками, дамп и
    импорт базы.
- Для каждого сценария указывается подтверждающий тест или «теста нет».
- Найденные неясности выносятся в design.md.

## Capabilities

### New Capabilities

- `platform/api-conventions`: общие правила HTTP API — ошибки, id запроса,
  журнал, CORS.
- `platform/runtime-config`: источники конфигурации, режимы окружения, проверки
  при старте, конфигурация для UI и проверка здоровья.
- `platform/data-maintenance`: миграции схемы, плановая очистка, дамп и импорт.

### Modified Capabilities

Нет.

## Impact

- Только `openspec/specs/`: три новые спецификации `platform/`.
- Код, API, БД и зависимости не меняются.
