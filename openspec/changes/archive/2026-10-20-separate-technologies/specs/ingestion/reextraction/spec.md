# Spec Delta

## ADDED Requirements

### Requirement: Администратор переразбирает вакансии без специализации
`POST /vacancies/reextract` MUST быть доступен только администратору и ставить LLM-задачу `reextract` (контракт — `platform/durable-jobs`) на активные вакансии не из HH с пустыми специализациями, не больше 500 за задачу, свежие первыми; список целей фиксируется при постановке. Ответ — 202 `{job_id}`; AI выключен или целей нет — 409.

#### Scenario: Не администратор
- **WHEN** запрос делает обычный пользователь
- **THEN** ответ 403

#### Scenario: Нечего переразбирать
- **WHEN** у всех активных вакансий не из HH есть специализация
- **THEN** ответ 409

### Requirement: Одна задача переразбора одновременно
Если задача `reextract` уже `queued` или `running`, `POST /vacancies/reextract` MUST возвращать 202 с её `job_id`, новая задача SHALL NOT ставиться. `GET /vacancies/reextract` отдаёт число целей, лимит задачи, признак включённого AI и id активной задачи.

#### Scenario: Повтор запроса
- **WHEN** переразбор уже идёт, а администратор снова вызывает `POST /vacancies/reextract`
- **THEN** ответ 202 с `job_id` идущей задачи

### Requirement: Переразбор обновляет разбор целиком и не удаляет вакансии
Каждая вакансия MUST разбираться LLM заново по своему тексту (без score-гейта) и записываться тем же UPSERT, что результат прогона. Итог по вакансии SHALL писаться в `llm_jobs.result` по мере обработки (`reextract_result` в `GET /llm-jobs/{id}`): `updated`; `kept` — LLM признал текст не вакансией, строка не меняется и не удаляется; `error` — ошибка LLM или вакансия удалена.

#### Scenario: Не вакансия
- **WHEN** LLM ответил `is_job_post=false` на переразбираемую вакансию
- **THEN** её статус `kept`, строка в БД не изменилась

### Requirement: Переразбор переживает сбой и отмену
Отмена MUST проверяться перед каждой вакансией; повтор после потери воркера SHALL продолжать с первой необработанной вакансии; без lease ни итог, ни вакансия не пишутся. Исчерпанная суточная квота останавливает задачу с предупреждением в итоге.

#### Scenario: Продолжение после сбоя
- **WHEN** задача упала после первой вакансии и выполняется снова
- **THEN** LLM вызывается только для необработанных вакансий

#### Scenario: Отмена
- **WHEN** отмену запросили после первой вакансии
- **THEN** вторая вакансия не разбирается, итог по первой сохранён
