# Proposal

## Why

Список вакансий сортируется только по одной колонке. Смотреть «свежие и дорогие»
нельзя: сортировка по дате идёт по времени поста, и зарплата внутри дня ни на что не
влияет. Кроме того, быстрой (по индексу) была только сортировка «дата ↓»: зарплата
сортировалась полным перебором совпадений, а дальние страницы любой сортировки
строили превью текста для каждой строки до OFFSET (30-я страница — 36 мс на 1.7 тыс.
активных вакансий, растёт с таблицей).

## What Changes

- Вторая ступень сортировки `then_by` / `then_order` в списке, экспорте и пресетах —
  только пара `post_date` ↔ `detected_salary_avg_rub`, другое сочетание — 422.
  `post_date` + зарплата: по дню поста (UTC), внутри дня — по зарплате, затем по времени.
  Зарплата + `post_date`: при равной зарплате — по дате.
- Равные значения сортировки (кроме `post_date` и `match_score`) идут от новых к старым,
  затем по `id` (раньше — сразу по `id`).
- Частичные индексы активных вакансий `ix_vacancies_active_day_salary` и
  `ix_vacancies_active_salary_date` (миграция 034) повторяют ORDER BY «день ↓ +
  зарплата ↓» и «зарплата ↓ + дата ↓».
- Одним запросом выбирается только первая страница индексируемой сортировки,
  остальные — в два (id, затем колонки и превью для них).
- UI: Shift+клик по «Дата» / «Зарплата, ₽» (или кнопка над таблицей) добавляет
  второй уровень; первый клик по числовой колонке сортирует по убыванию; дата в
  таблице — по UTC, как фильтры периода; экспорт из UI идёт в сортировке списка.
