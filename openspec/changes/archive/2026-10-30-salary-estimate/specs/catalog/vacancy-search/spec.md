# Spec Delta

## MODIFIED Requirements

### Requirement: Список сужается фильтрами каталога
Список вакансий MUST содержать только уникальные вакансии (без дублей дедупа), по умолчанию без архивных (см. `catalog/vacancy-retention`). Фильтры SHALL сочетаться через «и»: канал (`source_channel`, ведущий `@` отбрасывается), грейд, формат работы, любая из выбранных специализаций, любая из технологий, дата поста от и до включительно по UTC, `has_salary`: `true` — только с рублёвой суммой, `false` — только без неё. С `salary_estimates=true` вакансия с оценкой зарплаты (см. `catalog/salary-estimate`) считается для `has_salary` вакансией с зарплатой. Те же фильтры MUST действовать в метриках, аналитике и экспорте, кроме `salary_estimates`: метрики, аналитика и лист метрик экспорта его игнорируют.

#### Scenario: Несколько специализаций
- **WHEN** выбраны специализации `Backend` и `QA`
- **THEN** в списке вакансии, у которых есть хотя бы одна из них

#### Scenario: Специализация и технология
- **WHEN** выбраны специализация `Automation QA` и технология `Python`
- **THEN** в списке только вакансии `Automation QA`, у которых среди технологий есть `Python`

#### Scenario: Канал с `@`
- **WHEN** фильтр — `source_channel=@jobs`
- **THEN** список тот же, что при `source_channel=jobs`

#### Scenario: Граница периода
- **WHEN** `date_to=2026-09-30`, а пост опубликован 30 сентября в 23:59 UTC
- **THEN** вакансия входит в список

#### Scenario: Зарплата есть только в исходной валюте
- **WHEN** у вакансии A рублёвая сумма 150 000, у B зарплата 1 000 в валюте без курса, у C зарплаты нет
- **THEN** с `has_salary=true` в списке только A, с `has_salary=false` — B и C
- **AND** метрики с `has_salary=true` считают одну вакансию с зарплатой

#### Scenario: Оценка зарплаты в фильтре
- **WHEN** у вакансии A рублёвая сумма есть, у B нет, но есть оценка, у C нет ни того ни другого
- **THEN** с `has_salary=true&salary_estimates=true` в списке A и B, с `has_salary=false&salary_estimates=true` — только C
