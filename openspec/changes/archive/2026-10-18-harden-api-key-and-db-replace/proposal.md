# Proposal

## Why

Два найденных в baseline расхождения касаются защиты и сохранности данных.
`API_KEY` по README — дополнительный заголовок поверх JWT, но резюме, пресеты и
LLM-задачи его не проверяют: с утёкшим JWT к личным данным можно обратиться без
ключа. `db import --mode replace` молча удаляет каскадом оценки, письма и
LLM-задачи всех пользователей, хотя подтверждение говорит только о прогонах,
вакансиях, курсах и кэше.

## What Changes

- При заданном `API_KEY` заголовок `X-API-Key` проверяется на `/resumes/*`,
  `/filters/*` и `/llm-jobs/*`, как уже на остальных эндпоинтах с JWT. Поток
  событий LLM-задачи по одноразовому тикету ключа не требует, как и потоки
  прогона и HH. `/health` и `/auth/*` не меняются.
- `db import --mode replace` перед подтверждением считает и называет, сколько
  оценок соответствия, писем и LLM-задач удалится вместе с вакансиями; при отказе
  база не меняется. Формат дампа не меняется.
- README: описание `replace` исправлено (таблиц не четыре, каскад назван).

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `identity/access-control`: добавляется требование к общему API-ключу.
- `platform/data-maintenance`: добавляется требование к предупреждению перед
  заменой базы.

## Impact

- Код: `backend/api/routes/resumes.py`, `backend/api/routes/filters.py`,
  `backend/api/routes/llm_jobs.py`, `backend/db/transfer.py`,
  `tg_jobs_parser/cli/db.py`; новые тесты.
- API: при заданном `API_KEY` запросы к резюме, пресетам и LLM-задачам без
  `X-API-Key` получают 401. UI уже шлёт ключ на все запросы, клиенты без ключа
  при заданном `API_KEY` и раньше не работали с остальным API.
- БД и формат дампа не меняются.
