# Design

## Context

Мотивация — в `proposal.md`. Расхождения найдены в baseline: этап 1
(`baseline-invariants`, Open Questions 1) и этап 5 (`baseline-platform`, Open
Questions 4).

- Ключ проверяет `verify_api_key` (`backend/api/deps.py`): на роутерах прогонов,
  вакансий, аналитики, курсов, AI-кэша, конфигурации и HH он стоит в
  `dependencies`, на `/resumes`, `/filters` и `/llm-jobs` — нет. Потоки событий
  проверяют ключ сами в `authenticate_sse`: тикет — без ключа (его выдаёт
  `/auth/sse-ticket`, уже защищённый ключом), Bearer — с ключом.
- UI (`frontend/src/api/client.ts`) добавляет `X-API-Key` ко всем запросам, так что
  для него ничего не меняется.
- `replace` (`backend/db/transfer.py::import_database`) удаляет строки таблиц дампа;
  FK `ON DELETE CASCADE` на `vacancies` уносят `vacancy_matches`, `cover_letters`
  и `llm_jobs` с `vacancy_id`. Подтверждение — `typer.confirm` в
  `tg_jobs_parser/cli/db.py`.

## Goals / Non-Goals

**Goals:**
- Ключ проверяется одинаково на всех эндпоинтах с JWT.
- Перед `replace` администратор видит, какие данные пользователей потеряет.

**Non-Goals:**
- Ключ на `/auth/*` — решено оставить как есть (вход и обновление сессии без
  ключа).
- Перенос пользователей, резюме, пресетов, оценок и писем в дампе — формат
  дампа не меняется.
- Защита `replace` от удаления данных пользователей: `replace` по-прежнему
  оставляет в базе только вакансии из дампа.

## Decisions

### 1. Ключ на `/resumes` и `/filters` — на роутере, на `/llm-jobs` — на маршрутах

`/resumes` и `/filters` не содержат потоков событий: `Depends(verify_api_key)` в
`dependencies` роутера, как у остальных. В `/llm-jobs` поток событий живёт в том
же роутере, а его тикет-путь ключа не требует: зависимость ставится на
`GET /{job_id}` и `POST /{job_id}/cancel`. Альтернатива — вынести поток в
отдельный `sse_router`, как у прогонов и HH, — меняет регистрацию роутеров в
`backend/main.py` ради того же результата.

### 2. Подсчёт до подтверждения, в той же сессии

Функция в `backend/db/transfer.py` считает строки `vacancy_matches`,
`cover_letters` и `llm_jobs` с `vacancy_id`, которые удалит каскад при очистке
`vacancies`. CLI вызывает её перед `typer.confirm` и включает числа в текст.
Нули тоже показываются: текст подтверждения один для всех случаев.

## Risks / Trade-offs

- [Скрипт без `X-API-Key` к резюме, пресетам или LLM-задачам перестанет работать
  при заданном `API_KEY`] → это и есть исправление; README уже обещает ключ на
  всём API с JWT.
- [Число в подтверждении может устареть до очистки, если пользователи работают в
  это время] → `replace` и так требует остановленного трафика; число —
  предупреждение, а не гарантия.
