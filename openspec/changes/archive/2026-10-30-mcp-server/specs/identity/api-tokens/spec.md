# Spec Delta

## ADDED Requirements

### Requirement: Выпуск и хранение токена
`POST /auth/tokens` MUST выпускать токен `tgj_<случайная строка>` с именем (1–100 символов), scope'ами (`read` обязателен, `llm` — по желанию) и сроком 1–365 дней (по умолчанию 90) и возвращать его значение только в этом ответе (201); в БД SHALL храниться только sha256 значения и его начало для списка. Действующих токенов у пользователя MUST быть не больше 20 (иначе 409). `GET /auth/tokens` MUST возвращать неотозванные токены пользователя без значений; `DELETE /auth/tokens/{id}` — отзывать свой токен (204; чужой или уже отозванный — 404). Выпуск и отзыв MUST быть доступны только с access-токеном сессии (JWT), с PAT — 403.

#### Scenario: Значение не показывается повторно
- **WHEN** пользователь выпустил токен и запросил список
- **THEN** в списке есть имя, начало, scope'ы и срок, но нет значения

### Requirement: Аутентификация токеном и scope'ы
`Authorization: Bearer tgj_…` MUST приниматься всеми эндпоинтами, которые требуют вход, если токен не отозван, не истёк, пользователь активен и его `token_version` равна версии на момент выпуска (смена пароля и «выйти везде» отзывают PAT); иначе 401. GET/HEAD/OPTIONS MUST требовать scope `read`. Остальные методы MUST быть доступны токену только на эндпоинтах, помеченных `pat_scope("llm")` (постановка LLM-задач: оценка резюме, пакетная оценка, письмо, адаптация, подготовка к собеседованию, «Спросить базу»; отмена своей LLM-задачи), и только со scope `llm`; иначе 403 `FORBIDDEN`. Admin-эндпоинты MUST отвечать токену 403 даже у администратора. SSE-эндпоинты PAT не принимают.

#### Scenario: Токен только на чтение
- **WHEN** токен со scope `read` создаёт резюме или ставит оценку резюме
- **THEN** ответ 403 `FORBIDDEN`, а GET-запросы проходят

#### Scenario: Токен администратора
- **WHEN** админ обращается к `GET /runs` со своим PAT
- **THEN** ответ 403
