# Spec Delta

## ADDED Requirements

### Requirement: Пост с низкой оценкой не отправляется в LLM
Пост с `vacancy_score` ниже `ai.skip_if_vacancy_score_below` (0 — отправляются все) MUST отбрасываться без вызова LLM в обоих режимах. Ручной импорт этот порог не применяет.

#### Scenario: Оценка ниже порога LLM
- **WHEN** `ai.skip_if_vacancy_score_below: 3`, а у поста `vacancy_score` 1
- **THEN** LLM не вызывается, пост не сохраняется

### Requirement: Пост, который LLM признал не вакансией, отбрасывается
Если ответ LLM (вызовом или из кэша) содержит `is_job_post: false`, пост MUST отбрасываться в обоих режимах, даже если правила дали высокую оценку.

#### Scenario: Пост соискателя
- **WHEN** LLM вернул `is_job_post: false`
- **THEN** пост не сохраняется как вакансия

### Requirement: Отказ LLM на посте зависит от режима
Если вызов LLM для поста завершился ошибкой (после повторов и запасных моделей), пост MUST в `assist` сохраняться с полями правил, а в `primary` — отбрасываться и учитываться как ошибка LLM. Если LLM отключён на прогон (суточная квота, исчерпан общий лимит, circuit breaker), остальные посты SHALL в `assist` разбираться правилами, а в `primary` — отбрасываться. Условие `partial` для прогона описано в `parse-runs`.

#### Scenario: Ошибка LLM в assist
- **WHEN** в `assist` вызов LLM для поста упал
- **THEN** пост сохраняется с полями правил

#### Scenario: Квота исчерпана в primary
- **WHEN** в `primary` LLM отключился по квоте посреди прогона
- **THEN** оставшиеся посты, которым нужен вызов LLM, не сохраняются

### Requirement: Circuit breaker отключает LLM после серии ошибок
После `ai.circuit_breaker_errors` (5) постов подряд с ошибкой LLM MUST отключаться до конца прогона, чтобы остальные посты не ждали повторов. Успешный ответ SHALL сбрасывать счётчик подряд идущих ошибок.

#### Scenario: Серия ошибок
- **WHEN** 5 постов подряд получили ошибку LLM
- **THEN** LLM отключается, следующие посты не вызывают LLM

#### Scenario: Ошибки вперемешку с успехами
- **WHEN** ошибки LLM перемежаются успешными ответами
- **THEN** LLM не отключается

### Requirement: Транзиентные ошибки повторяются, клиентские — нет
Транзиентный сбой вызова LLM (5xx, таймаут) MUST повторяться до `ai.max_retries_on_error` (2) раз с растущей задержкой от `ai.retry_base_delay_seconds`; `0` отключает повторы. Клиентская ошибка (4xx, кроме 429) SHALL NOT повторяться. Rate limit определяется по HTTP-статусу 429, а не по тексту ошибки.

#### Scenario: Сервер вернул 503
- **WHEN** первый вызов вернул 503, второй — таймаут, третий — ответ
- **THEN** пост разобран, сделано 3 попытки с паузами между ними

#### Scenario: Ошибка 400
- **WHEN** вызов вернул 400
- **THEN** повторов нет

### Requirement: Запасные модели пробуются по порядку
Если основная модель не ответила (кроме rate limit и исчерпанной квоты), MUST по порядку пробоваться модели `ai.fallback_models` (пусто — запасные по умолчанию из `llm_models.yaml`, без основной и без повторов). Ошибка всех моделей SHALL считаться ошибкой LLM на посте.

#### Scenario: Основная модель недоступна
- **WHEN** основная модель вернула ошибку, первая запасная ответила
- **THEN** пост разобран ответом запасной модели

#### Scenario: Текст ошибки содержит «429»
- **WHEN** ошибка основной модели не 429 по статусу, но «429» есть в её тексте
- **THEN** запасная модель всё равно пробуется

### Requirement: В assist LLM уточняет поля правил по уверенности
В `ai.mode: assist` поле из ответа LLM MUST заменять поле правил, только если оно в `ai.merge.prefer_ai_for` и `confidence` ответа не ниже `ai.merge.min_confidence` (0,45); иначе LLM SHALL лишь заполнять пустые поля правил (зарплата, формат, локация, компания, контакт, опыт, занятость). Специализации и технологии объединяются; грейд берётся от LLM только при выполнении условия и если он не `unknown`. `extraction_source` — `hybrid`.

#### Scenario: Уверенный ответ
- **WHEN** в `assist` LLM с уверенностью 0,85 вернул зарплату и формат работы, которых нет у правил
- **THEN** зарплата и формат берутся от LLM, специализации — объединение правил и LLM, источник `hybrid`

#### Scenario: Неуверенный ответ
- **WHEN** в `assist` LLM с уверенностью ниже 0,45 вернул другой грейд, чем правила
- **THEN** остаётся грейд правил

### Requirement: В primary поля берутся только от LLM
В `ai.mode: primary` специализации, грейд и зарплата MUST браться только из ответа LLM, даже если LLM вернул `unknown` или пустую зарплату; специализации правил не используются. Остальные поля LLM SHALL заполнять или заменять, технологии объединяются. `extraction_source` — `ai`.

#### Scenario: LLM не нашёл зарплату
- **WHEN** правила нашли зарплату, а LLM в `primary` вернул пустую
- **THEN** зарплата вакансии пуста

#### Scenario: Специализации правил по подстроке
- **WHEN** правила нашли специализацию по случайной подстроке, а LLM её не вернул
- **THEN** у вакансии только специализации от LLM

### Requirement: Ответ LLM кэшируется по тексту, модели, версии промпта и режиму
Ответ LLM MUST кэшироваться по ключу из текста (обрезанного до `ai.max_input_chars`), модели, версии промпта извлечения (`EXTRACT_PROMPT_VERSION`) и режима; запись живёт `ai.cache_ttl_days`. Ответ запасной модели SHALL сохраняться под ключом запасной модели, а не основной. Смена версии промпта даёт промах кэша.

#### Scenario: Ответ запасной модели
- **WHEN** пост разобран запасной моделью
- **THEN** ответ кэширован под запасной моделью; следующий прогон с той же основной моделью снова спрашивает основную

#### Scenario: Запись кэша истекла
- **WHEN** запись кэша старше TTL
- **THEN** она не используется
