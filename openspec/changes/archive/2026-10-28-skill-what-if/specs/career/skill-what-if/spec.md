# Spec Delta

## ADDED Requirements

### Requirement: Сегмент и подходящие вакансии
`GET /resumes/{id}/what-if` MUST считать по 200 уникальным вакансиям, ближайшим к резюме по эмбеддингу за 365 дней (с архивом), с непустыми технологиями. Вакансия MUST считаться подходящей, если резюме называет не меньше 70% её технологий; технология засчитывается резюме так же, как в «Резюме и рынок». Чужое резюме — 404; эмбеддинги выключены или недоступны — 503 `UPSTREAM_UNAVAILABLE`. LLM SHALL NOT вызываться.

#### Scenario: Покрытие ниже порога
- **WHEN** резюме называет 2 из 3 технологий вакансии
- **THEN** вакансия не подходит (67% < 70%)

### Requirement: Варианты технологий
Вариант MUST быть технологией, которой нет в резюме, нужной не меньше чем в 5 вакансиях сегмента и 3% их; многословные названия только из кириллицы (практики) SHALL NOT быть вариантами. Для варианта MUST возвращаться: число вакансий, где он нужен; сколько вакансий станут подходящими, если добавить только его; рост среднего покрытия; премия — в самом частом грейде сегмента, если грейд вошёл в сравнение, иначе средневзвешенная по грейдам самой частой роли сегмента за год, иначе null. Варианты MUST идти по убыванию новых подходящих, затем спроса; не больше 12.

#### Scenario: Технология закрывает порог
- **WHEN** в 6 вакансиях [Python, Pytest, Selenium], а резюме знает Python и Pytest
- **THEN** у Selenium спрос 6 и +6 подходящих

### Requirement: Сочетания
`peer_gaps` MUST содержать по каждой вакансии сегмента с технологиями число её технологий, число названных в резюме и недостающие из вариантов, чтобы эффект нескольких технологий считался без запроса к серверу.

#### Scenario: Две технологии вместе
- **WHEN** вакансии [Python, Pytest, Docker, Kafka, Helm] и резюме знает Python и Pytest
- **THEN** ни Docker, ни Kafka по отдельности их не закрывают, а `peer_gaps` показывает 5 технологий, 2 покрыто, Docker и Kafka недостают
